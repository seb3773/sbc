# sbc — Super Byte Compact 0.970 Archiver (Native C Reimplementation)

Pure C standalone reimplementation of the historical **Super Byte Compact (SBC) archiver version 0.970** (2000–2008, by Sami Runsas).

> **Reverse Engineering & Legal Notice:** This work was conducted strictly for the purposes of software interoperability and digital data preservation (under European Directive 2009/24/EC) to reconstruct the proprietary compression, transformation, and encryption algorithms of an obsolete archive format.

This repository provides a complete, freestanding, zero-dependency C implementation combining both **decompressor** (`sbc x`) and **compressor** (`sbc c`) into a single binary (`sbc`), achieving **100% bidirectional bit-exact compatibility** with the original historical Windows x86 binaries (`sbc.exe` and `unsbc.exe`).

---

## Highlights

- **100% Bit-Exact Parity with Original Archiver**:
  - Every archive generated by this reimplementation matches the binary output of the historical Windows `sbc.exe` **byte-for-byte** across all 126 tested configurations.
  - Decompression has been verified across 100% of reference test corpora without a single discrepancy.
- **Complete Feature Set**:
  - **All Compression Modes**: Full support for Mode 0 (Adaptive Arithmetic), Mode 1 (LZP + BWT), Mode 2 (LZP + BWT High), Mode 3 (BWT Max), Mode 4, Mode 5, Mode 6, and Mode 7 (periodic spacing filter).
  - **Transformations & Filters**: Exact Bentley-McIlroy 3-way BWT sorting, LZP window pre-pass, Prediction by Partial Matching / Structured Subfilters, delta filters, run-length encoding, MTF (Move-To-Front), and range coding.
  - **Comprehensive Cryptographic Suite**: Embedded freestanding implementations of all 7 historical symmetric ciphers (AES / Rijndael, Blowfish, CAST-128, DES, Triple-DES, Serpent / TNEPRES, Twofish) with identical key schedule and CFB/CBC streaming modes.
  - **Multi-File & Multi-Block**: Complete handling of solid archives, block streaming (`-b1`..`-b5`), file ordering flags (`-on`, `-of`, `-oa`, `-oz`, `-os`), and hash algorithms (`-hn`, `-hc`).
- **Zero External Dependencies**:
  - Pure standard C99 with freestanding cryptographic kernels.
  - Compiles cleanly on modern Linux and cross-compiles to standalone Windows 64-bit binaries via MinGW-w64.
- **Comprehensive Documentation**:
  - [FORMAT.md](FORMAT.md): Exhaustive binary layout and bitstream specification.
  - [ENCODER.md](ENCODER.md): Complete specification of the heuristic planner, transformations, and compression engine.

## Build

### Using `build.sh`

```sh
./build.sh            # Production Linux build -> build/linux/sbc (symlink ./sbc)
./build.sh win64      # Production Windows 64-bit static build -> build/win64/sbc.exe
./build.sh all        # Build both Linux and Windows 64-bit binaries
./build.sh debug      # Build with debug symbols (-g -O0)
./build.sh test       # Run self-test and verification test suite
./build.sh clean      # Clean build artifacts
```

### Using `make`

```sh
make                  # Compile Linux binary (-O3 -flto)
make win64            # Cross-compile Windows 64-bit static binary
make all-platforms    # Build all targets
make test             # Run self-test and corpus test suites
make deb              # Build standalone Debian .deb package
make dist             # Build complete release distribution (.tar.gz, .zip, .deb)
make clean            # Remove build directory
sudo make install     # Install to /usr/local/bin
```

### Manual Compilation

```sh
# Native Linux
gcc -O3 -flto -fomit-frame-pointer -Wall -Wextra -Isrc -o build/linux/sbc src/sbc.c -lm

# Windows 64-bit (via MinGW-w64)
x86_64-w64-mingw32-gcc -O3 -flto -Wall -Wextra -Isrc -static -o build/win64/sbc.exe src/sbc.c -lm
```

## Usage

```
sbc <command> [options] <archive.sbc> [files...]
```

### Commands

| Command | Action | Description |
|---|---|---|
| `c` | **Create** | Create an archive and compress files (`-m1`..`-m3`, `-b1`..`-b5`) |
| `x` | **Extract** | Extract files from archive into target directory |
| `l` | **List** | List files, uncompressed sizes, and metadata |
| `t` | **Test** | Verify archive integrity and checksums |

### Common Options

| Option | Description |
|---|---|
| `-m1` | Fast compression (LZP + BWT) |
| `-m2` | Normal compression (LZP + BWT with extended search) |
| `-m3` | Maximum compression (BWT Max, default) |
| `-b1`..`-b5` | Block size threshold (from 256 KB up to 4 MB) |
| `-k<cipher>` | Symmetric encryption cipher (`aes`, `blowfish`, `cast`, `des`, `3des`, `serpent`, `twofish`) |
| `-p<password>`| Encryption passphrase |
| `-hn` / `-hc` | Checksum algorithm (None / CRC32) |
| `-ad` | Enable advanced dynamic mode selection |
| `-af` | Force specific filter analysis |
| `-on` / `-of` / `-oa` / `-oz` / `-os` | File ordering strategy (by Name, Format, Access, Size, Solid) |
| `-u`, `--unix` | Format paths as Unix relative paths (`/` slashes, lowercase) |
| `-1`, `--bare` | Bare listing (one path per line, script/pipe friendly) |

### Security & Zip-Slip Protection

- **Path Traversal & Zip-Slip Protection**: Validates all extraction paths with `is_safe_relpath()`.
- **Nesting Depth Tracking**: Continuously tracks directory nesting depth; any attempt to ascend above the destination root via `../` (or `..\`) is intercepted and rejected with a security warning (`Security warning: skipping unsafe path traversal`).
- **Drive Identifier & Absolute Path Rejection**: Immediately rejects leading slashes (`/`, `\`) and DOS drive identifiers (`C:`).
- **DOS Backslash Sanitization**: Automatically normalizes historical DOS backslashes (`DIR\SUBDIR\FILE.TXT`) to forward slashes `/` on POSIX systems, ensuring safe, seamless directory hierarchy recreation.

### Examples

```sh
# Create an archive with maximum compression (M3)
./sbc c archive.sbc file1.txt file2.bin

# Create an encrypted archive using Twofish
./sbc c -ktwofish -pSecretKey safe.sbc confidential.pdf

# List contents of an archive
./sbc l archive.sbc

# Bare listing with Unix-formatted relative paths (ideal for xargs, grep, scripts)
./sbc l -1 -u archive.sbc

# Test integrity of an archive
./sbc t archive.sbc

# Extract archive to destination directory (with path traversal protection)
./sbc x archive.sbc output_dir/

# Extract archive converting historical paths to Unix lowercase
./sbc x -u archive.sbc output_dir/
```

## Technical Architecture

The SBC compression process consists of a sequential, multi-layered pipeline:

1. **Analysis & Filter Selection**:
   - The encoder samples byte distributions, entropy, and periodic autocorrelation to select between Mode 0..Mode 7.
   - Text structures and multi-byte tables undergo delta passes or Mode 7 spacing alignment.
2. **Pre-Coding (LZP)**:
   - Repetitive text or structured data passes through an LZP (Lempel-Ziv-Poisson) filter with a 2 MB sliding window.
3. **Stage 2 (BWT / Adaptive Arithmetic)**:
   - Block-sorting via a specialized Bentley-McIlroy 3-way quicksort, reproducing identical pivot selection and ties resolution.
   - Output passes through Move-To-Front (MTF) and run-length encoding.
4. **Entropy Coding**:
   - Bit planes and statistical distributions are compressed via a precise Range Coder.
5. **Encryption Layer**:
   - Encrypted archives derive session keys and IVs using the user password, streaming cipher blocks in CFB/CBC mode before writing to disk.
